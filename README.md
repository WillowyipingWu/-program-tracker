# Program Tracker · 选校追踪

输入学校和项目名（例如 `Michigan IOE MS`），自动读取**官网招生页面**，整理出截止日期、申请材料和关键要求，并生成可勾选的追踪清单。

每一条结果都带有官网原文引用，程序会检查这段引用**是否真的出现在页面上**，日期是否与引用吻合。查不到的、对不上的，会明确标出，而不是悄悄当成事实。

> ⚠️ **请以官网为准。** 结果由 AI 从网页提取，可能出错或过期。标着"未能核对"的条目务必人工确认。

## AI Key：BYOK（Bring Your Own Key）

**这个项目不提供共享的 AI Key，也不内置任何人的密钥。** 部署这个网站的人（下文称"部署者"）不需要、也不应该在服务器上配置一个大家共用的 Key。

每个访问者在网页右上角的设置面板里填入**自己的** API Key（豆包/火山方舟 或 Claude 均可）：

- 这个 Key 只会随这一次查询发给**部署者自己的服务器**，再由服务器原样转发给访问者选择的模型服务商，用完即走——服务器不记录、不落盘、不写入缓存。
- 访问者勾选"记住在本设备"后，Key 才会明文存进**访问者自己浏览器**的 localStorage；不勾选的话，关闭标签页就清空。
- 导出的 JSON 里不包含 Key。

这样设计是为了让这个工具可以放心公开部署：部署者不用担心陌生访客用自己的账单跑查询，访客也清楚自己的 Key 去了哪里、停在哪里。

**部署者唯一需要配置的是非敏感信息**：`.env` 里的 `ARK_MODEL` / `ANTHROPIC_MODEL` 是模型名称，不是密钥，可以预先填好，这样访客就不用自己去找模型 ID；`ARK_BASE_URL` 同理是接口地址。**`ARK_API_KEY` / `ANTHROPIC_API_KEY` 这两项请保持空白**——只有在你确定这个部署只有你自己会用（比如本地跑给自己用）时，才可以临时填一个当作默认值，但要清楚这样做之后，任何能访问到这个服务器的人都能花掉这个 Key 的额度。

想在部署前用自己的 Key 跑一次健康检查（不经过网页），可以在 `.env` 里临时填上 `ARK_API_KEY`/`ARK_MODEL`，运行 `npm run check`，确认没问题后再把 Key 从 `.env` 里删掉、改为真正的公开模式。

## 工作原理

```
项目名 ──► ① 找官网 URL ──► ② 抓取真实页面正文 ──► ③ 模型只从正文里提取（必须引用原文）──► ④ 校验引用
          (搜索 / 手动粘贴)     (含 SSRF 防护)          (豆包 或 Claude)                    (原文里有吗？日期对吗？)
```

关键设计：**搜索只负责找到链接，答案只来自抓到的官网正文，不来自搜索摘要。** 搜索摘要往往过时或不完整，这是自动化版本最容易出错的地方。

## 快速开始

需要 Node.js 20+，**无第三方依赖**，不用 `npm install`。

```bash
npm test                  # 先跑测试（不需要 API Key，不联网）
cp .env.example .env      # Windows 用 copy .env.example .env；按需填模型名称（不是密钥）
npm run dev               # 启动，打开 http://localhost:3000，在网页的设置面板里填入你自己的 API Key 测试
```

想先用自己的 Key 做一次命令行自检（不经过网页），临时在 `.env` 里填 `ARK_API_KEY`/`ARK_MODEL`，运行 `npm run check`，测完记得把 Key 删掉再部署。

## 配置（环境变量）

| 变量 | 说明 |
|---|---|
| `LLM_PROVIDER` | 设置页默认选中哪个服务商：`ark`（豆包）或 `anthropic`（Claude）。访客仍可在网页里改选 |
| `ARK_MODEL` `ANTHROPIC_MODEL` | **非敏感**的默认模型名称，访客不填时使用；留空则访客必须自己填模型名 |
| `ARK_BASE_URL` | 方舟接口地址。**只认这里的值，拒绝任何来自请求的覆盖**（防止被当成 SSRF 跳板） |
| `ARK_API_KEY` `ANTHROPIC_API_KEY` | **留空。** 只有纯个人部署才可以临时填，填了就等于所有访客共用这个 Key，详见上面的 BYOK 说明 |
| `SEARCH_PROVIDER` | 服务器自身测试用的搜索开关，默认 `none`；访客的自动搜索走的是设置面板里的勾选项，用的是访客自己的 Key |
| `RATE_LIMIT_PER_HOUR` | 每个 IP 每小时最多查询次数（默认 20，缓存命中不计）。这里限的是服务器带宽/算力，不是 AI 费用——费用由访客自己的 Key 承担 |
| `CACHE_TTL_DAYS` | 结果缓存天数（默认 7），缓存内容不含任何人的 Key |
| `TRUST_PROXY` | 部署在反向代理后面时设为 `1` |

### 关于豆包（方舟）

- 抽取步骤使用方舟的 OpenAI 兼容 `chat/completions` 接口。
- 访客在设置面板勾选"自动搜索官网"时，会用方舟 Responses API 的联网搜索工具（同一把访客自己的 Key）。**这部分请求格式我没有条件实测**，建议先自己用 `npm run check` 之外的方式（比如先不勾选自动搜索，手动粘贴链接跑通）验证提取效果，再评估搜索命中率，并对照最新的[方舟文档](https://www.volcengine.com/docs/82379/1399009)核对接口格式。
- 豆包的搜索资料库偏中文内容，对美国大学官网的覆盖可能不稳定，这也是为什么默认不勾选自动搜索、鼓励手动粘贴链接。
- 方舟的结构化输出目前是 beta，所以本项目不依赖它：自己解析 JSON、失败重试一次、再逐项校验。

## 安全与成本

- **Key 的生命周期**：访客的 API Key 随请求体发到你的服务器，服务器只在内存里用它调用一次模型 API，然后随请求结束丢弃；不写日志、不进缓存、不落盘。缓存（`.cache/`）里存的只有提取结果，不含 Key。
- **SSRF 防护**：两层。(1) 抓取官网页面前解析 DNS，拒绝内网/本机/云元数据地址，重定向逐跳复检；(2) 调用模型 API 的目标地址（`ARK_BASE_URL` / `api.anthropic.com`）完全由部署者的 `.env` 决定，请求体里任何试图指定地址的字段都会被忽略，访客拿不到让服务器访问任意地址的能力。已知局限：页面抓取部分不防 DNS rebinding，公开部署建议再加网络层隔离。
- **限流**：进程内滑动窗口，限制的是服务器自身的带宽/算力消耗（抓页面、处理请求），不是 AI 调用费用——那是访客自己的 Key 在付费。单机够用，多实例部署请换成 Redis 等共享存储。
- **部署者自己的 Key 不要进 `.env`**（见上面的 BYOK 说明），`.gitignore` 已排除 `.env`，但仍建议提交前手动检查一遍，确认没有把任何人的 Key 带进 git 历史。
- 用户的勾选数据和（选择"记住"后的）API Key 只存在各自浏览器的 localStorage 里，服务器不保存。

## 已知局限

- 只读 HTML 和纯文本。**PDF、需要登录的页面、纯 JavaScript 渲染的页面读不到**（会在提示里说明）。
- 页面太长会被截断（会提示）。
- "已核对"只说明引用确实在你抓到的页面上，**不保证页面本身是最新的**，也不保证模型选对了相关段落。
- 一个项目的信息常分散在院系页和研究生院页，目前最多同时读取 3 个页面。

## 目录

```
server.js          HTTP 服务、限流、缓存
lib/research.js    主流程
lib/fetchPage.js   抓取 + HTML 转文本
lib/ssrf.js        内网地址防护
lib/extract.js     提示词、JSON 解析、引用校验
lib/providers.js   豆包 / Claude 的模型与搜索封装（按请求构造，不是启动时固定一份）
scripts/check-ark.js  部署者自用的命令行自检（npm run check），不是访客走的路径
public/index.html  前端（无构建步骤）
test/              单元与端到端测试
```
